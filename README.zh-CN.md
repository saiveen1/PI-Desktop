# PI-Desktop · 个人版

> **当前发布线：0.23.x。**

独立维护的本地优先 AI Agent 工作台，重点投入**执行框架加固、多 Agent 协作和日常使用体验**。

本版本基于[上游 PI-Desktop](https://github.com/vastsa/PI-Desktop)，会持续跟进上游更新，
在保留本地功能与修复的基础上评估、合并适用改动；功能与发布节奏独立演进。

[English](README.md)

## 本版本新增、加固与关键修复

以下介绍的是**在上游基础上的本地增量**，不是上游功能目录。内容对应当前源码，可能晚于
[已记录版本](CHANGELOG.md)。[改动来源说明](docs/maintenance/personal-edition-provenance.md)
记录了对照版本、原始提交、实现依据及排除的上游功能。
当前源码版本为 `0.23.1-beta.1`，部分新流程仍需更广泛的集成验证；版本号不代表稳定性、
已发布版本或安装升级已经得到保证。

### Harness 加固：让执行、工具调用与恢复有明确边界

Harness 指控制 Agent 执行、工具调用和恢复的框架。本版本在既有框架上加固，而不是另起一套。

- **本地工具观测**：开发者选项从有界的本地日志汇总工具结果和后台任务终态，支持查看分组事实，
  并将脱敏报告追加到对话草稿。不自动发送、不调用模型、不重放命令；覆盖限制和未知结果明确显示。
- **本地性能诊断**：明显卡顿或主窗口渲染进程异常退出时，即使没有开始录制，也会把近期进程采样保存到本地事件日志。
  可从「设置 → 信息 → 开发者选项 → 性能诊断」查找日志。仍可手动录制最长 30 秒，预览并导出更详细的报告。
  未测到的指标不记为零；不记录或上传聊天内容。

- **扩展重复失败保护**：在既有 Edit／补丁保护之外，覆盖 Write 和相同 Bash 命令的重复同类失败。
  实际修改文件后允许重新验证；拿到完整的新上下文时保留有限恢复机会。
  Host 容量拒绝单独计数，不再当成补丁写错。
- **先检查准入，再执行**：后台命令先预约容量再启动进程，落实单会话 shell 数量限制，
  并为完成／取消操作保留 Host 处理容量。审批等待不再消耗工具请求的整体截止时间，
  实际执行期限仍然有效。
- **工具参数更容易纠正**：兼容带 tag 或空白可选 tag／ops 默认值的受支持旧式 Edit 替换参数，
  明确指出冲突插入位置，修正后台等待／停止时的任务选择；不放宽文件版本、已读上下文和授权校验。
  切换前台工作区不再丢弃后台会话已记录的读取范围。
- **可配置的有限纠正，减少无声停工**：普通 Agent 承诺下一步却未调用工具就停止时，可只提示，
  或在选定的纠正额度内续接。清单续跑与文本工具调用纠正共用额度，不叠加新的预算。
  清单检查读取宿主已绑定的会话，即使该会话未关联项目。
  正常检查不增加模型上下文或评审请求；实际续接可能增加用量，仍不保证任务完成。
- **对话内可选 Observer Guard**：在输入栏选择观察或防护，在行为设置中独立选择模型和思考强度。
  观察只提供评估建议；防护须通过证据及安全检查，并在已有纠正额度内续接。整轮摘要固定展示检查、
  跳过和阻止续跑的原因，可跳转查看已记录证据；回答结束后补写的评估可在重载后保留，旧记录缺失的
  原因仍标为未知。简短续接指令会附带有长度上限、经过脱敏的任务前文和最近回答，并以独立历史证据 ID
  区分；缺失上下文仍不能授权执行。独立评审不会占用或替换主对话在服务商侧的消息续接状态。
  关闭时不增加请求；启用会增加费用和等待时间，不复评续跑后的输出，也不证明任务完成。
- **可配置的退化输出保护**：检测并中断长串空白／符号或持续完全重复的自然语言段落，
  在行为设置中调整开关和阈值；保留已有结果，不自动重放。代码和结构化示例不参与段落比较。
  这不是对所有重复文句或回答质量的通用评判。对于 DeepSeek 回复，对话视图还会隐藏正文里反复出现的
  裸思考结束标记，不修改原始回复或模型回放数据。
- **等待与上下文由运行时控制**：主会话模型请求可配置连接空闲策略，不再把每次输出停顿都当作
  需要重放的请求；触发本地空闲截止后由用户决定重试。上下文压缩不再通过模型工具主动触发，
  保留既有的自动压缩与用户 `/compact` 入口。
- **运行时明确告知主模型身份**：主 Agent 可读取当前请求的精确模型 ID 和 provider ID，切换模型后同步
  更新，用于回答自身模型和填写要求的 `AI-Model` 尾注，无需猜测。这确认的是请求配置，不是网关隐含路由。
- **压缩后延续执行进度**：主会话活动任务的检查点除了摘要，还保留当前请求、预算内的近期进展和成对的
  工具调用／结果，重启后也能恢复，不再只靠摘要记住刚做过什么。长结果的摘要输入保留两端，
  并标明未纳入视觉内容的图片；续接提示区分已完成、待完成及结果未知的操作。
  已结束任务不会重新带回旧请求。这能减少上下文丢失，但不保证模型永不重复或外部操作恰好执行一次。

### 子代理协作：调度、审批、跟进与恢复

- **统一模型池与审批**：增加分组模型审批、可恢复的审批入口、策略热更新，以及会话级候选模型池
  和审批覆盖设置；按需提供模型描述以便按任务选择。角色未固定推理档位时，每次委派可独立请求比主会话更高或更低的 effort。可配置的失败处理仍受模型授权约束。
- **会话与全局任务索引**：从聊天顶部打开当前会话的子代理，或在跨项目历史中查看已记录的模型、
  完成时间、输出令牌数和明确标注口径的任务／请求吞吐量。旧记录缺失的数据保持不可用，吞吐量不等于
  纯生成速度；保留的历史审批结果也不代表再次执行的授权。
  聊天条目和会话索引用独立子代理图标／标签区分思考，直接展示已记录的模型与 effort。
  后台刷新不挤动列表；更新失败时保留原有信息并明确提示。
- **进展检查点与直接跟进**：保留可配置运行预算，自动保存的检查点补充有界工具证据、确认写入的路径
  及副作用未知的待完成操作。
  运行时区分安静的工具、等待模型和未观察到新证据，不暗设强杀期限，也不强制模型定期写进度报告。
  本地 Agent 会话中可向运行中的子代理补充指令，或显式恢复已结束任务；恢复会保留已记录的模型、选模理由和请求的 effort，并明确显示为续接而不是新任务；查看历史不会重启任务。
- **更准确的交付与恢复判定**：不把旧进度文字或截断结尾当成最终报告，合并重复恢复请求，
  支持在下一次用户输入时接回此前被父任务失败打断的工作。
  固定工具子代理可加载技能而无需继承无关的插件／MCP 执行工具；每个角色可继承可用技能、
  选择特定技能 ID 或不加载技能。这不会授予技能描述中的工具或权限。
  授权、模型请求尝试、执行结束与报告交付分别记录，不必打开原始日志才能区分。

### 会话组织与通知

- **快速翻到更早的提问**：已加载的最早位置落在折叠的长工具回合里时，可直接定位到上一条提问，
  不必逐页加载中间的工具记录。工具明细仍可按需加载。

- **编辑最后一条助手回答**：在空闲的本地对话里改好回答并保存，下一轮模型读到的就是修改后的回答，不会重新生成。可选择从后续上下文仅排除最终答案附带的思考（默认）、这次回答过程中的全部思考，或保留这次回答的全部思考；不影响更早的对话，原思考仍可在历史里查看。要改更早的回答，先在那条回答处分叉，再编辑副本。

- **项目内分组、彩色标签与可控排序**：分组决定摆放位置，多标签不会重复生成会话条目。
  本地项目各组显示完整数量并独立分页。收起的分组也可显示运行中、待处理和未读结果。
  项目「＋」可选组，分组「＋」可直接在该组创建。新建后展开目标组；打开已有会话不改变分组的展开状态。
  从会话或某条回复分叉时，新会话自动留在原会话的分组。
  手动移动和已接受的用户发送会更新活动顺序；只是打开聊天或接收流式输出不会改变顺序。
  在会话菜单中可标为已读或未读；未读标记保存在本机，重新打开会话时清除。
- **显式勾选与可恢复删除**：在原有快捷键多选基础上增加勾选框、选择操作和批量归档／取消归档。
  本地 Desktop 会话增加回收站、恢复及需单独确认的永久删除；不覆盖原生 Pi 与远程会话。
- **统一核心通知策略**：审批、提问、失败和完成共用渠道／声音设置，待处理操作与历史记录分开。
  通知带你回到相关入口，不会替你批准或重启任务。
  委派声音设置支持按草稿音量试听；刷新恢复的审批不会重播首次提示音，已配置的重复提醒仍会持续到请求结束。

### 聊天、文件与图片体验

- **任务优先的阅读方式**：活动与思考默认折叠，用紧凑任务列表和失败摘要呈现过程，复用主／子任务
  详情展示；运行中、已停止或失败时，也能查看已记录的文件改动。
  作答后，主聊天记录会在提问的位置逐题显示问题和回答，不随工具活动折叠。
- **扩展聊天文件操作**：增加另存为、支持的文本内容复制，将“打开方式”从 HTML 扩展到普通文件的
  默认应用。本地会话无论是否绑定项目，普通磁盘文件的拖入、粘贴和文件选择均使用实时引用，不再复制全文
  或受文件传输体积限制；图片与生成的剪贴板内容保留附件处理。引用不是快照，读取仍遵守工具权限。
- **工具图片连续可用**：保留历史预览；Read 返回图片时，调用行直接显示数量和缩略图，
  无需展开工具详情，也不会在回答末尾重复展示。修复图片在后续请求和子代理模型上下文中的保留与传递，
  模型能力或图片限制阻止传递时明确提示。原生 Responses 生图结果会保存并显示引用，不再静默丢失；
  纯图片回复和交付失败不会自动重复生成。预览仍遵守原有上限，较大图片保留文件访问入口。

### 日常使用中的关键修复

- **保留 Responses 流式内容**：本地兼容修复避免空白终态覆盖已输出的有效思考与回答，
  也防止纯零宽占位摘要覆盖思考。纯不可见占位不再生成空的思考展开栏；不影响后续真正生成的思考。
  同时保留正常的最终修订和拒绝。聊天中能明确识别的 DSML 尾片段默认收在「协议详情」里，
  可展开查看原文；实际执行状态以工具记录为准。详见[诊断与限制](docs/maintenance/responses-terminal-content-loss.md)；
  此改动无法恢复此前丢失的内容。

- **修复多 Agent 并发下的文件工具连锁阻塞**：解决长时间搜索持有 Host 范围的文件锁，导致其他会话
  读写连续准入超时、多个代理无法修改文件的问题。改为逐文件协调，并补齐取消与资源释放处理，
  同时保留同一文件的读写保护。
- **阅读恢复与历史回复分叉**：修复切换会话和延迟历史读取的竞态，避免旧恢复结果覆盖新的阅读意图，
  或丢掉已经加载的历史范围。翻页、搜索定位或恢复阅读后，旧回复即使不在最新消息缓存中也能创建分支，
  不改写原会话内容，也不中断后续正在运行的轮次。
  打开长会话或恢复阅读位置不再自动翻读历史。需要时向上滚动，或点「显示更早的消息」；
  即使最近内容不足一屏，也可以手动翻页。
- **执行结果更清楚**：区分失败、拒绝、跳过、中断和需要补充上下文，保留阶段／重试诊断，
  清理陈旧的运行中标记和重试提示；同时修复重命名输入反复全选、折叠审批入口干扰输入框的问题。
- **针对性的 Windows 与路径修复**：让裸文件名沿用 Markdown 中明确给出的目录，
  在 Windows 上可打开 Git Bash 格式的链接（`/d/...`），隔离 worktree 中打开对应的分支副本。
  未继承编码偏好时，将执行器子进程的 Python 标准流默认设为 UTF-8。
  Git Bash 前台／后台执行器保留命令中的反斜杠和带引号 heredoc 的原文，不改写已审批命令或自动重放失败。
- **数据目录迁移兼容**：修复 Windows 路径写法变化导致项目级能力开关覆盖设置失效的问题，
  并在迁移时重映射本地会话组织数据的项目路径；沿用既有迁移流程。

## 从源码运行

需要 Node.js `>=22.19`、pnpm `>=10` 和稳定的 Rust 工具链；Windows 还需 MSVC Build Tools。
在源码目录执行：

```bash
pnpm install
pnpm dev
```

本版本的 `pnpm dev` 默认清除继承的数据目录覆盖设置，不要让它使用正在运行的安装版配置目录。
检查命令与显式复用数据的规则见[开发流程](docs/spec/06-delivery/03-ai-development-workflow.md)。

默认在当前工作区开发；确有并发修改时再按需使用 worktree。复用缓存，不用跨工作区链接
共享可写源码或依赖目录。获准清理后，必须先拆除目录链接再让 Git 删除；详见
[隔离与清理规则](docs/spec/06-delivery/03-ai-development-workflow.md#isolation-is-a-reason-not-a-ritual)。

Windows 运行 [start-local.cmd](start-local.cmd) 即可编译必要的当前源码并在同一控制台启动，
无需打包、安装或输入确认。先配置被 Git 忽略的 `start-local.data-dir.local`，
并退出所有使用该目录的进程。**默认不备份**；只有传入 `-BackupConfig` 才会将应用偏好、
用户服务及模型定义导出到 `<data-directory>.config-backups`，不会复制数据库、会话、
附件或凭证。依赖包会在启动前重建，匹配不到依赖时直接停止。启动器不会停止进程。
使用前请阅读[启动器说明](docs/spec/06-delivery/03-ai-development-workflow.md#windows-local-source-launcher)；
`start-local.cmd -CheckOnly` 仅检查前置条件，不启动应用。

## 个人 Windows 构建

个人打包流程面向 **Windows 10/11 x64**，生成禁用官方自动更新的 NSIS 安装包。
每次构建都附带唯一标识、源码元数据、从 Git 历史生成的变更说明和 SHA-256 校验值。
主进程打包保留启动所需的 Photon 解码器 WASM，安装包检查会拒绝缺失或损坏的副本。
构建清理只处理临时产物，不删除以往安装包。

```bash
pnpm dist:personal --check  # 预览构建计划，不执行构建
pnpm dist:personal          # 构建，不改变应用版本
```

产物位于 `apps/desktop/release/personal/`。**打包不会安装或启动应用。**
候选版本发布、验证范围和产物详情见[个人发布说明](docs/spec/06-delivery/07-personal-release-runbook.md)。

### 使用 GitHub Actions 构建

个人 fork 的 [Personal Windows 工作流](.github/workflows/personal-windows.yml)
在代码推送到 `main` 后构建，不修改已提交的版本号。版本号不变时，只上传安装包和溯源文件作为
Actions 产物，保留 30 天；推送将版本升为更新的 beta 时，构建通过后还会为该提交发布 `personal-v`
预发布版本。也可手动运行：`release_version` 留空则只构建，填写更高的 beta 则由 Actions 升版并发布。
两种方式都不会开启已安装应用的自动更新。详见
[Actions 发布说明](docs/spec/06-delivery/07-personal-release-runbook.md#github-actions-personal-fork-only)。
